# Мост 3.0

Файлы, общие папки, пространства и записи между своими ПК — плюс каналы с голосом, показом экрана, общей доской и чатами. Одна программа: `Мост.exe` — своё окно (Tauri 2 + WebView2) и значок у часов; `bridge.exe` — то же без окна, для консоли и скриптов.

## Из чего состоит проект

| Папка | Что там |
|---|---|
| `core/` | общие типы, настройки, подписи (Rust) |
| `node/` | сам мост: сеть, папки, пространства, каналы, доска, локальный API; `bridge.exe` |
| `app/` | окно приложения (Tauri 2) и значок у часов; узел работает в том же процессе; `Мост.exe` |
| `ui/` | панель: Svelte 5 + TypeScript + Vite. Готовая сборка (`ui/dist`) вшивается в программу |
| `node/assets/` | телефонная страница, окно показа, шрифты и значки |
| `API.md` · `CHANGELOG.md` | локальный API для ассистента · что нового |

В гит не попадают сборка (`target/`, `publish/`), `ui/node_modules`, `ui/dist`, журналы и данные запущенного моста — см. `.gitignore`.

## Сборка и установка (Windows)

1. Один раз: `winget install Rustlang.Rustup` (установщик предложит Visual Studio Build Tools — согласиться) и `winget install OpenJS.NodeJS.LTS`. Новое окно консоли. WebView2 в Windows 10/11 уже есть.
2. В папке проекта: `build.cmd` → `publish\Мост.exe` и `publish\bridge.exe`. `build.cmd notest` — без тестов.
3. Закрыть старый «Мост» (значок у часов → Выход), положить оба файла в его папку рядом с `bridge.json`, запустить `Мост.exe`.

Новая установка: запустить `Мост.exe` в любой папке, куда можно писать (например `C:\Bridge`) — создаст `bridge.json` с именем ПК и его адресами и откроет панель на «Соседях».

Разработка панели: запустить мост, затем `cd ui && npm run dev` — Vite на своём порту проксирует API на `127.0.0.1:5390`. Проверка типов — `npm run check`.

Проверка на Linux/macOS: `cargo test --release -p bridge-core -p bridge-node`, `cargo run --release -p bridge-node -- run` (панель — в браузере).

## Сети и адреса

Мост сам слушает на всех сетях ПК тем же портом (`listenAuto`, по умолчанию включено): локальная сеть, Radmin, ZeroTier — и подхватывает сеть, появившуюся позже (раз в 30 с). Адреса сообщаются соседям в привете, вписывать их не нужно. Чужих не пустит белый список и подпись; панель и локальный API — только с этого ПК. Выключить: `"listenAuto": false` (тогда — только адреса из `listen`).

Если связь в одну сторону, «🩺 Проверить» на том ПК, до которого не достучаться, скажет точно: «мост не слушает адрес X», «такого адреса у ПК нет» или «слушает — значит, брандмауэр» (Windows обычно считает сеть Radmin общественной — разрешение нужно и для общественных сетей).

## Окно приложения

Панель открывается в своём окне, а не в Edge/Chrome: запросы к мосту идут внутри программы (без сети и без ключа), окно помнит положение, крестик прячет его к часам. Нет WebView2 — панель откроется в Edge/Chrome, как раньше. Ссылки открываются в браузере, «⧉ в отдельном окне» — отдельным окном приложения.

## Защита при управлении ПК

Пока соседу разрешено управлять этим ПК:
- **мост заперт** — менять настройки, права, папки, разрешения и т. п. нельзя (ответ 423); работают только голос, показ, доска, чат и «Остановить»;
- щелчки и клавиши соседа **не доходят до окон самого моста**;
- клавиша **Pause** на этой клавиатуре сразу отзывает управление (нажатие, присланное соседом, не считается).

## Значок у часов

Точка состояния (зелёная — все на связи, жёлтая — кто-то недоступен, красная — ошибка) и счётчик ожидающего. Щелчок — окно панели, правая кнопка — меню: панель, обменяться, папки, уведомления, автозапуск, выход. Всплывающие уведомления: сосед на связи/пропал, файл, задача, звонок, просьба показать экран.

## Права и группы

- `groups` в `bridge.json`: `{"family": {"title": "Семья", "members": ["papa-pc", "masha"]}}`.
- В доступе папки и в участниках пространства вместо имени соседа — `@группа`: `"access": {"@family": "read", "@work": "write", "kolya": "write"}`. У соседа действует большее из прав (напрямую, через группы, `*`).
- Вкладка «Права и группы»: группы и таблица «кто что видит» с источником права; щелчок по клетке — нет → чтение → запись.

## Каналы: голос и экран

Как в Discord: **канал** — комната, куда заходят, когда хотят (`channels` в bridge.json или «＋ Канал» в панели: название и кто может зайти — соседи, `@группа`, `*`). Канал живёт на ПК владельца; соседи узнают о нём из привета и видят у себя. Кто в каком канале и что делает — видно, не заходя.

- **Войти** — сразу в разговоре; **войти тихо** — без звука входа у остальных. Пока звучит приветствие, плитка вошедшего мигает.
- Файлы, брошенные на плитку участника, уходят ему.
- Микрофон, звук («не слышать никого»), рация на пробел, громкость каждого, выбор микрофона.
- Значки у всех участников видят все: микрофон выключен, звук выключен (красный — только они), показывает (синяя рамка и значок экрана), смотрит (чей показ); говорящий подсвечен зелёным.
- **Показ экрана идёт в канал**: каждый сам включает просмотр; видео передаётся только смотрящим. Можно показывать **несколько окон сразу**. Чужой показ — **⧉ в отдельном окне** (на другой монитор; несколько окон одновременно).
- **Своя плитка:** картинка или гифка фоном с маской, прозрачностью и оттенком, форма и размер аватарки, цвета рамки, имени и подсветки («Настройки» → «Плитка и аватарка»).
- **Доска канала:** рисование, фигуры, текст тремя шрифтами (Простой, Техно, От руки) с размером и стилем, заметки, картинки, PDF, слои, фон; ассистент работает с ней через API (`board/*`, MCP `bridge_board`).
- **Диаграммы (3.3):** фигуры (22 вида) и связи, которые едут за фигурами; «+» и Tab для быстрого продолжения, направляющие, выравнивание и авто-раскладка, шаблоны, Mermaid туда и обратно (`ui/src/voice/diagram.ts`).
- **Агент на этом же ПК (3.3):** `agent_ask` без `peer` — мост запускает отдельный Claude здесь.
- **📞 Позвонить** — разговор без канала, у выбранных звонит; «🙋 попросить экран» — просьба показать.
- Участники, которые не соседи друг другу, обмениваются сигналами через ПК владельца канала; звук и видео — напрямую.

Устройство: WebRTC в панели. Каждый участник раз в 5 с и при изменениях рассылает своё состояние (`media/signal`, `type: state`); с каждым — одно соединение с «вежливыми переговорами» (perfect negotiation), сообщения одному собеседнику — строго по очереди. Opus 64 кбит/с, без STUN/TURN (LAN/Radmin); адреса `.local` браузера мост подменяет на настоящий адрес соседа.

## Передачи

- Плашка в углу панели на любой вкладке: что передаётся, кому/от кого, процент, скорость, сколько осталось (`GET transfers`). Видно у обеих сторон.
- Файлы больше 8 МБ в общих папках идут в фоне — мелкие не ждут.
- «Общие папки» → «Настройки передачи»: **скорость отдачи и приёма** (Мбит/с, общая на все передачи; пусто — без ограничения), **предел размера файла** (пусто — без предела; прежние 512 МБ по умолчанию снимаются сами), корзина. В bridge.json: `maxUpMbit`, `maxDownMbit`, `maxFileMb`.
- Файл больше предела владельца не отправляется: у папки — понятная строка, повторных попыток нет.

## Агенты: Claude поручает Claude

Claude на одном ПК (оркестратор) поручает задачи Claude на другом (исполнитель) и получает ход работы и итог. Поручение — «нить»: продолжение идёт в той же сессии Claude (`--resume`), исполнитель помнит контекст.

- **Исполнитель** (`agent` в bridge.json или «Агенты» в панели): `mode` — `off` / `auto` (мост сам запускает `claude -p --output-format stream-json --permission-mode auto`, поручение — через stdin, ход — в реальном времени) / `manual` (поручение ждёт сессию Claude на этом ПК: `agent_take` → `agent_progress` → `agent_report`). `allowFrom` — кто может поручать; `workDir`, `claude` (путь к claude.exe, пусто — найти), `permissionMode`, `maxMinutes`, `maxParallel`, `maxBudgetUsd`.
- **Оркестратор**: инструменты моста для Claude — `bridge mcp` (MCP по stdin/stdout). Подключить: `claude mcp add --scope user bridge -- "C:\Bridge\bridge.exe" mcp --config "C:\Bridge\bridge.json"` (точная строка — в панели, «Агенты» → «Подключить к Claude»). Инструменты: `bridge_peers`, `agent_ask`, `agent_wait`, `agent_status`, `agent_stop`, `agent_threads`, `exchange_folder`, `send_file`; для ручного режима — `agent_wait_task`, `agent_inbox`, `agent_take`, `agent_progress`, `agent_report`.
- **Обменная папка**: своя общая папка с правом записи у исполнителя (`agent.exchange`, «＋ обмен с …»). Её путь на ПК исполнителя мост передаёт его Claude вместе с поручением.
- Протокол соседей: `POST /peer/agent/ask`, `POST /peer/agent/events` (ход исполнитель → оркестратор, раз в 0.5 с), `POST /peer/agent/stop`, `GET /peer/agent/thread`; в привете — `agent` (режим для спрашивающего). Нити хранятся в `bridge-data/agent/*.json` у обеих сторон.
- Локальный API: `GET agent`, `POST agent/settings`, `POST agent/ask {peer,prompt,thread?}` (peer пусто / `local` — поручение этому ПК), `GET agent/thread?id&after`, `GET agent/wait?id&after&timeout`, `POST agent/stop?id`, `POST agent/delete?id`, `GET agent/inbox`, `GET agent/wait-task?timeout`, `POST agent/take?id`, `POST agent/progress`, `POST agent/report`, `POST agent/exchange?peer`. Событие SSE `agent`.

Записи можно удалять: `bridge delete <id>` / действие `delete` (пометка `deleted`, доходит до всех узлов, вернуть — `restore`).

## Телефон

Мост открывается в браузере телефона (Android): отправить файлы, фото, текст на ПК или соседу, получить файлы с ПК, посмотреть общие папки.

1. Панель → «Телефон» → «Подключить телефон» → отсканируйте QR-код камерой телефона.
2. Дома телефон подключается по Wi-Fi. Чтобы работало и вне дома — поставьте **Tailscale** на ПК и телефон (одна учётная запись) и нажмите «Включить HTTPS». Если Tailscale попросит включить HTTPS для сети — панель покажет ссылку.
3. По HTTPS мост можно установить как приложение («Добавить на главный экран») — он появится в меню «Поделиться».

С телефона на ПК файлы попадают в «приём/<имя телефона>». С ПК на телефон — папка «на телефон/<имя телефона>» или перетаскивание на вкладке «Телефон». Доступ телефона — полный или «только файлы»; отключить — кнопка «Отключить».

## Ассистент

Если на одном из ПК семьи работает ассистент (Telegram-бот и т. п.), в панели всех ПК появляется вкладка «Ассистент» — чат: текст, голос, файлы, ответы с кнопками. Напоминания приходят всплывашкой в трей со звуком; будильник звенит, пока не выключат. Кто может писать ассистенту — `assistant.allowFrom` (по умолчанию все соседи). Подробности для разработчика ассистента — API.md, раздел «Ассистент».

## Голос с телефона

Вкладка «Голос» на телефоне: каналы, звонки, показ экрана. Говорить можно, когда мост открыт по HTTPS (Tailscale); по обычному адресу телефон только слушает. Если телефон и сосед не видят друг друга напрямую (Wi-Fi и Radmin), звук идёт через ретранслятор моста на вашем ПК — порт UDP 3478 (`turnPort`, 0 — выключить). Брандмауэр Windows при первом запуске спросит разрешение — разрешите для частных сетей.

## API для ассистента

Всё, что делает панель, — локальный HTTP `http://127.0.0.1:<порт>/bridge/v1/local/…`, заголовок `X-Bridge-Local: <bridge-data/local.token>` (для потоков можно `?token=`). Перечень с параметрами: `bridge api GET api`. Полное описание записей, действий и файлового интерфейса `_bridge/` — в README 1.4 (раздел 8), оно не менялось.

Новое в 2.0:

| Вызов | Что |
|---|---|
| `GET events` (SSE) | Поток событий: `peer-online`, `peer-offline`, `peer-named`, `file-in`, `mailbox-received`, `mailbox-sent`, `record`, `records-in`, `command-waiting`, `media-invite`, `folder-write` |
| `GET groups`, `POST groups {id,title,members}`, `POST groups/remove?id` | Группы |
| `GET access` | Кто что видит: строки-соседи, папки и пространства, источник права (`direct`, `via: ["@family:read"]`, `all`) |
| `POST folders {id,title,path,access}` | `access` принимает `@группа` |
| `GET channels`, `POST channels {id,title,members}`, `POST channels/remove?id` | Каналы: свои и видимые у соседей, кто где (`presence`) |
| `GET media/presence` | Кто в каком канале: микрофон, звук, показы, кто что смотрит |
| `POST media/signal {to,media,type,room,…}`, `GET media/stream` (SSE), `GET media/invites` | Сигналинг голоса/экрана; ассистент может, например, позвать в разговор или увидеть входящий звонок |
| `GET transfers` | Идущие передачи: кто, что, сколько из скольки, скорость, осталось |
| `POST folders/settings?upMbit&downMbit&maxFileMb&trashMinutes` | Ограничение скорости, предел размера, корзина |

Пример: ассистент подписан на события и пересылает в Telegram пришедшие файлы:

```
curl -N "http://127.0.0.1:5390/bridge/v1/local/events?token=$(cat bridge-data/local.token)"
event: bridge
data: {"kind":"mailbox-received","time":"…","data":{"peer":"alfa","path":"alfa/отчёт.pdf","size":48211}}
```

Отправить файл: `bridge send kolya отчёт.pdf` или `POST mailbox/upload?peer=kolya&path=отчёт.pdf` (тело — файл). Дать семье доступ к папке: `POST folders {"id":"foto","path":"D:\\Фото","access":{"@family":"read"}}`.

## Устройство

```
core/   формат и логика без сети: config (bridge.json, группы, доступ), signing (HMAC, kid), scanner (обход + кэш хешей),
        files (решения о скачивании, конфликты), events/reducer/records (записи), proto (сетевые DTO), time (.NET-совместимое)
node/   узел: node.rs (главный цикл), link.rs (подключение, адреса, 🩺 проверка), shares.rs, folders.rs, mailbox.rs,
        media.rs (сигналинг), board.rs (доска), remote.rs (управление ПК и его защита), http_peer.rs (/peer/…, подпись),
        http_local.rs (/local/…, раздача панели из ui/dist), main.rs (CLI); build.rs вшивает ui/dist
app/    Мост.exe: Tauri 2 (окно WebView2, протокол bridge:// прямо в мост), значок Win32, уведомления, автозапуск,
        клавиша Pause, оверлей пометок поверх экрана
ui/     панель: src/App.svelte, tabs/ (вкладки), modals/, components/, voice/ (каналы, доска, показ), lib/ (API, состояние)
```

Протокол соседей тот же, что у 1.4 (подпись HMAC-SHA256, `kid` ключа, откат на старую подпись для соседей до 1.4). Добавлено, обратно совместимо: `hello.revs` и `SharedFolderInfo.rev` (отпечатки), `/peer/signal`.
