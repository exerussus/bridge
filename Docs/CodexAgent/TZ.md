# Мост: Codex как агент-исполнитель — ТЗ

Ред. 1, 2026-11-10. Основа — `Brief.md` (ред. 2) и проба `share\output\codex-probe` (Codex 0.167.0). Версия моста — **3.24.0**.

## 0. Решения

| Вопрос | Решение |
|---|---|
| Сколько движков на ПК | **Один движок на исполнителя**: `agent.engine = claude \| codex`. Поручение идёт тем движком, который выбран у исполнителя. Отдельного выбора движка в поручении нет. Отправитель видит движок соседа в «Кому». |
| Сеть в песочнице Codex | Выключена по умолчанию (`codexNetwork: false`). Генерации картинок она не нужна: Codex ходит к генератору своим соединением. |
| Где Codex пишет | Рабочая папка — `workDir` моста. Обменная папка нити и `codexDirs` передаются через `--add-dir`. Конкретный путь результата указывает поручение. |
| Картинки | Источник истины — `%USERPROFILE%\.codex\generated_images\<thread_id>\*.png`. Мост сверяет эту папку с `IMAGE:`-строками и докладывает то, что Codex не скопировал. |
| Стоимость | Codex её не сообщает. У нити копятся токены, `cost` = 0. |
| Самооценка Codex | Мост её не толкует. Итог — только текст и файлы; оценку делает оркестратор. |

Совместимость: все новые поля аддитивные. Старый `bridge.json`, старые соседи и старые нити читаются как раньше (`engine` пусто → `claude`).

## 1. Настройки (`core/src/config.rs`, `AgentConfig`)

| Поле (JSON) | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `engine` | string | `"claude"` | Чем исполнять поручения (`claude` \| `codex`). Неизвестное значение → `claude` + предупреждение в журнал. |
| `codex` | string | `""` | Путь к `codex.exe` / `codex.cmd`. Пусто — искать (см. 3.1). |
| `codexSandbox` | string | `"workspace-write"` | `read-only` \| `workspace-write` \| `danger-full-access`. Иное → `workspace-write`. |
| `codexNetwork` | bool | `false` | `true` → `-c sandbox_workspace_write.network_access=true`. |
| `codexModel` | string | `""` | `-m <model>`, пусто — модель из настроек Codex. |
| `codexDirs` | string[] | `[]` | Дополнительные папки с правом записи (`--add-dir`). Относительные — от папки моста (`node.resolve`). |

`maxMinutes`, `maxParallel`, `allowFrom`, `workDir`, `exchange`, `extraArgs`, `fileChannel` — общие для обоих движков. `permissionMode`, `maxBudgetUsd` и `claude` — только для Claude. `extraArgs` добавляются к командной строке активного движка.

## 2. Протокол

### 2.1 Hello (`core/src/proto.rs`, `HelloResponse`)

Новое поле рядом с `agent`:

```rust
/// (3.24) Движок агента для спрашивающего: «claude» | «codex»; пусто — claude (старый мост) или агент не принимает.
#[serde(default, skip_serializing_if = "String::is_empty")]
pub agent_engine: String,   // JSON: agentEngine
```

- `http_peer.rs::hello`: заполнять `agent_engine` вместе с `agent` (только если `agent_allows`).
- `link.rs`: `s.agent_engine = hello.agent_engine.clone()`, новое поле в `PeerState` (`node.rs`).
- `http_local.rs::agent_get`: в каждом соседе — `"engine": s.agent_engine`; в `local` — `"engine": cfg.agent.engine`.

### 2.2 Поручение (`/peer/agent/ask`, `agent::ask_full`, `enqueue`)

Новое необязательное поле `images: string[]` — картинки на вход. Пути относительны обменной папки нити (`<exchange>/<path>`). Абсолютные пути и `..` отклоняются с ошибкой 400.

- У исполнителя `images` хранится в нити (`Thread.inputs`, только для последнего поручения).
- Claude: картинки дописываются в поручение строкой «Входные картинки: <абсолютные пути>».
- Codex: передаются флагами `-i <абс. путь>` и тоже перечисляются в поручении.
- Файл не найден к моменту запуска → ждать до 30 с (папка может досинхронизироваться), затем `fail` «нет входной картинки <путь> в обменной папке».

### 2.3 Ход (`/peer/agent/events`, `pusher` → `on_events`)

В теле пуша добавляются поля:

- `engine`;
- `tokens {input, cached, output}`;
- `images: [{path, size, w, h}]` — пути относительны обменной папки.

`on_events` принимает их так же, как `cost`/`turns`: если ход устаревший (`stale`), `images` не трогаются.

### 2.4 Нить (`Thread`)

```rust
pub engine: String,                 // claude | codex; пусто = claude
pub tokens: Tokens,                 // {input, cached, output}: i64, копятся за все ходы
pub images: Vec<ImageOut>,          // {path, size, w, h} — все картинки нити, по порядку появления
pub inputs: Vec<String>,            // входные картинки последнего поручения (исполнитель)
```

`engine` фиксируется при создании нити:
- у исполнителя — из `agent.engine`;
- у заказчика — из `agentEngine` соседа (в момент ask);
- `local` — из своей настройки.

Если движок исполнителя сменили, а нить продолжают, — `fail` «нить начата движком X, сейчас у исполнителя Y — начните новую нить». Сессию одного движка другой не продолжит.

## 3. Исполнитель Codex (`node/src/agent.rs` → новый модуль `node/src/agent_codex.rs`)

`schedule` вызывает `run_claude` или `run_codex` по `t.engine`. Общее с Claude: процессы, `kill_tree`, предел времени, стоп, `fail`, `pusher`. Вынести общий запуск процесса из `run_once` в функцию `spawn_lines(exe, args, stdin, cwd, cancel, deadline, on_line) -> (exit, stderr_tail, timed_out)`. Её используют оба движка; разбор строк — свой у каждого.

### 3.1 Поиск `find_codex`

Порядок поиска:
1. Настройка `codex`.
2. PATH: `codex.exe`, затем `codex.cmd`.
3. `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe` — так ставит официальный установщик, подтверждено пробой.
4. `%APPDATA%\npm\codex.cmd`.

`.cmd` запускается как `cmd.exe /C "<путь>" <аргументы>` (Rust не стартует `.cmd` напрямую). Аргументы с пробелами и кириллицей — в кавычках; проверить на пути `C:\Bridge\общие-мои\…`.

Не найден → `fail`: «не найден Codex. Установите: PowerShell → `irm https://chatgpt.com/codex/install.ps1 | iex` (или npm i -g @openai/codex), затем один раз `codex login`. Или укажите путь в «Агенты» → «Путь к codex».»

### 3.2 Командная строка

Новая нить:

```
codex exec --json --skip-git-repo-check
  -s <codexSandbox> -C <workDir>
  [--add-dir <обменная папка нити>] [--add-dir <каждый из codexDirs>]
  [-c sandbox_workspace_write.network_access=true]
  [-m <codexModel>]
  [-i <вход>]...
  [extraArgs]
  -
```

Продолжение (`t.session` не пуст):

```
codex exec resume <t.session> --json --skip-git-repo-check [те же -c/-m/-i/extraArgs] -
```

Правила:
- Поручение подаётся через stdin, последним аргументом идёт `-`. Флаг `-i` жадный: без `-` или `--` в конце он съедает промпт («No prompt provided»).
- У `resume` набор флагов уже, чем у `exec`. Пробой (п. 7, шаг 2) выяснить, принимает ли `resume` флаги `-s`, `-C`, `--add-dir`. Что не принимается — передавать через `-c` (`sandbox_mode=…`) или не передавать. Рабочая папка задаётся `current_dir` процесса.
- Окружение процесса: `BRIDGE_AGENT_THREAD=<id>`, `CREATE_NO_WINDOW` (как у Claude).
- В нить пишется `info` «Codex запущен (песочница …, сеть выкл/вкл)».

### 3.3 Поручение (stdin)

Поручение = блок «Положение исполнителя» + пустая строка + текст поручения.

Блок «Положение исполнителя» строится через `context_prompt`/`finish_prompt`, адаптированные к движку: «Ты — Codex-исполнитель…». Для Codex из `finish_prompt` убирается абзац про `agent_request` (MCP моста Codex не подключается, см. п. 8) и добавляется:

> Картинки рисуй только встроенным инструментом генерации изображений — не через API, не скриптом. Каждую готовую картинку сохрани по пути из поручения (если путь не указан — в обменную папку, подпапка `<id нити>`). В конце хода перечисли каждую сохранённую картинку отдельной строкой `IMAGE: <полный путь>`. Писать можно только в рабочую и обменную папку.

### 3.4 Разбор `--json` (`handle_codex_line`)

| Строка | Действие |
|---|---|
| `thread.started {thread_id}` | `t.session = thread_id`; запомнить `t0` хода (для картинок). |
| `turn.started` | — |
| `item.completed`, `item.type = agent_message` | `push("text", text)` + `phase_of` (Этап/Ожидание); запомнить как последний текст хода. |
| `item.started`, `command_execution` | `push("tool", "Команда: " + короткая команда)`. Команду показывать без обёртки `powershell.exe -Command "…"` и кавычек — только суть, до 160 символов. Если `t.status == waiting` → `running`. |
| `item.completed`, `command_execution` | Только при `exit_code ≠ 0` или `status = failed`: `push("info", "команда: код N — <хвост вывода 300>")`. |
| `item.*`, `file_change` | `push("tool", "Файлы: " + пути через запятую)` (по `completed`). |
| `item.*`, `mcp_tool_call` | `push("tool", "<server>.<tool>")`. |
| `item.*`, `web_search` | `push("tool", "Поиск: <query>")`. |
| `item.*`, `todo_list` | Первая незавершённая задача → `set_phase` (без события). |
| `item.*`, `reasoning` | Не пишется. |
| `item.*`, `error` | `push("info", "Codex: " + message)`. |
| `turn.completed {usage}` | `tokens += {input_tokens, cached_input_tokens, output_tokens + reasoning_output_tokens}`; `turns += 1`; собрать картинки (3.5); `status = idle`, `result` = последний `agent_message`; `push("result")`. Уведомление и `emit` — как у Claude, но с токенами вместо $. Возврат true. |
| `turn.failed {error}`, `error {message}` | `status = failed`, `error` = сообщение. Возврат true. |
| Не JSON / неизвестный тип | Пропустить. Каждая сырая строка дописывается в `bridge-data/agent/<id>.codex.jsonl`. Чистка — вместе с нитью и по `keepHistoryDays`. |

Процесс кончился без `turn.completed`/`turn.failed` → `fail` «Codex завершился без итога (код N)» + хвост stderr. Подсказка по stderr:
- есть `login` / `auth` / `401` → «войдите: codex login»;
- есть `No prompt provided` → «ошибка запуска (поручение не дошло) — сообщите разработчику моста».

### 3.5 Картинки после хода (`collect_images`)

1. `gen = %USERPROFILE%\.codex\generated_images\<t.session>\`. Новые файлы — `*.png` с `mtime ≥ t0` хода.
2. Строки `IMAGE: <путь>` из всех `agent_message` хода. Путь нормализовать; файл должен существовать и лежать в обменной папке нити или в `codexDirs`, иначе игнорировать с `info`.
3. Каждой новой картинке из `gen` сопоставить сохранённую копию: файл того же размера и с тем же md5 среди путей из шага 2.
   - Копии нет → мост сам копирует её в `<обменная>/<id нити>/codex-<имя>.png`.
   - Обменной папки нет → копирует в `workDir/images/<id нити>/`, а в нить пишет `info` «обменная папка не настроена — картинка только на исполнителе».
4. Для каждого итогового файла:
   - `push("tool", "Картинка: <путь относительно обменной>")`;
   - добавить в `t.images` `{path, size, w, h}`. `w`, `h` читаются из заголовка PNG (IHDR), без декодирования.
5. Если `gen` нет (старый Codex, другой путь), брать только `IMAGE:`-строки. Журнал `.codex\sessions\…\rollout-*.jsonl` мост **не** читает.

### 3.6 Стоп, время, параллельность

- Как у Claude: `stop_local` → отмена → `kill_tree` (Codex порождает `powershell.exe`).
- `maxMinutes` — общий. Одна генерация идёт 35–95 с; по умолчанию для Codex советуем 15 мин (подсказка в панели, не жёстко).
- `maxParallel` — общий. Параллельные `codex exec` проверить в шаге 5 приёмки.

## 4. Проверка движка (`GET agent/codex-check` → `{found, path, version, login}`)

Запуск `codex --version` и `codex login status` с таймаутом 15 с каждый; `login` — первая строка вывода.

Вызывается:
- кнопкой «Проверить Codex» в панели;
- при сохранении настроек с `engine = codex` (результат — подсказкой под полем).

## 5. Инструменты (`node/src/tools.rs`, MCP и efc «agent-channel»)

- `bridge_peers` — к строке соседа дописать движок: «Taranis NoteBook — Codex запустится сам». Шапка «Этот ПК» — с движком.
- `agent_ask`: новый параметр `images` (string[], пути относительно обменной папки). В описание добавить: «Если исполнитель — Codex: картинки он рисует встроенным генератором; укажи, куда сохранить (путь в обменной папке), и какой размер — формат берётся из входной картинки-шаблона».
- `agent_wait` / `agent_status`: в ответе — `engine`, токены вместо $ (если `engine = codex`) и список `images` (`путь · w×h`) с полными путями **на этом ПК** (обменная папка у себя + относительный путь).
- `agent_channel` (efc) использует те же определения — отдельной работы нет. Проверить, что `images` проходит через файловый канал.

## 6. Панель (`ui/src/tabs/Agent.svelte`, `components/AgentAsk.svelte`)

### 6.1 «Этот ПК — исполнитель»

- Под режимом — переключатель «Движок: Claude / Codex» (виден при `auto`; при `manual` — только Claude, Codex в ручном режиме не поддерживается, подпись об этом).
- При `Codex` блок настроек Claude (путь к claude, разрешения, бюджет) скрыт. Вместо него показываются:
  - «Путь к codex» с подписью «найден: …» / «не найден»;
  - «Песочница» (`read-only` / `workspace-write` / `danger-full-access`);
  - флажок «Сеть для команд Codex»;
  - «Модель» (пусто — по умолчанию);
  - «Папки с записью» — по одной на строку;
  - кнопка «Проверить Codex» → «версия 0.167.0 · Logged in using ChatGPT» или ошибка.
- `maxMinutes` / `maxParallel` — общие, остаются видны.

### 6.2 «Поручить» → «Кому»

Подпись соседа зависит от `engine`:
- `codex` → «Taranis NoteBook — Codex запустится сам»;
- `claude` / пусто → как сейчас.

Для `local` подпись берётся из своей настройки.

### 6.3 Нить

- В шапке и в списке нитей: значок движка. Вместо «$0.57» для Codex — «12.3k ток.» (сумма `input + output`; в подсказке — разбивка с кэшем).
- Событие `tool` с префиксом «Картинка:» показывается как превью 96 px по высоте. Источник — файл в обменной папке на этом ПК, через существующую раздачу файлов общей папки. Если файла ещё нет (не досинхронизировался) — серый квадрат «ждёт синхронизации».
- Под итогом — лента всех `t.images` нити. Клик открывает картинку в `Lightbox`.
- Подпись страницы: «Claude или Codex на одном ПК выполняет поручения Claude с другого — и присылает отчёт».
