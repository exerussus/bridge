# Журнал изменений

## 3.9.0 — 29.10.2026
- **Постоянное разрешение приложений** — как в Android.
  - При разрешении можно выбрать: «Только эту версию» (как раньше: при обновлении мост спросит снова) или **«Постоянно»**.
  - При постоянном разрешении обновления принимаются без вопроса, если издатель тот же, а прав и адресов в интернете не прибавилось. Новые права, новые адреса или другой издатель — мост спросит снова и скажет почему.
  - Для приложения без подписи «постоянно» означает, что любое изменение его файлов на этом ПК примется без вопроса. Мост предупреждает об этом: такой выбор подходит для своих приложений.
- **Автозапуск вместе с мостом.**
  - **Фоновая служба** работает всё время, пока работает мост: упадёт — поднимется сама, при обновлении перезапустится с новым кодом.
  - **Своё окно** открывается при запуске моста. Закроете его — до следующего запуска моста оно само не откроется.
  - Так пульт телевизора и принтер включаются сами. Приложение может предложить автозапуск (`"autostart"` в app.json), но включает его только хозяин ПК.
- **Настройки приложения** — правая кнопка по ярлыку → «Настройки приложения…». Там:
  - постоянное разрешение;
  - автозапуск службы и окна;
  - **права переключателями** (выключили право — приложение перезапускается уже без него);
  - подписи вашим ключом без вопроса — со снятием;
  - данные приложения с размером и кнопкой «Очистить» (в корзину моста);
  - кнопки «Открыть», «Остановить», «Отозвать разрешение», «Убрать».
- **«Настройки» → «Приложения»** — все приложения этого ПК: как разрешено, что запускается с мостом, что сейчас работает. Щелчок открывает настройки приложения.
- **Подпись вашим ключом — «Разрешать всегда».** Вопрос о подписи теперь отдельным окном: «Не подписывать», «Разрешить сейчас» (до перезапуска моста) или «Разрешать всегда» — тогда разрешение хранится в настройках приложения.
- Приложения сами эти настройки менять не могут. Пока ПК управляют по сети, и с телефона они тоже недоступны.
- Исправлено: окна, которые после закрытия ещё обращались к своим данным, могли дать ошибку в панели.
- API:
  - `POST apps/allow {id, perms, trust?, autostart?: {service, native}}`;
  - `POST apps/settings {id, trust?, autostart?, perms?, signRevoke?}`;
  - `POST apps/data/clear {id}`;
  - `POST apps/identity/answer {…, always}`;
  - в `GET apps` у приложения — `consent {trust, autostart, signAllowed, at, version, updated}`, `changeWhy`, `dataSize`, `suggestAutostart`, `serviceAlways`.

## 3.8.0 — 28.10.2026
- **Сборки — отдельный раздел** в меню слева, под «Отправкой». Внутри две вкладки: «Присланные мне» и «Мои сборки».
- **Присланные мне.** У каждой сборки, которую прислали соседи, видно:
  - номер последней версии и когда она пришла, патчем или целиком, сколько файлов;
  - **что нового** — заметку отправителя;
  - **историю версий** с заметками;
  - кнопки «Папка» и «Куда…».
- **«▶ Запустить».** Если отправитель указал, что запускать, у получателя есть кнопка запуска. Пока программа работает, видно «запущено» и кнопку «Остановить». Первый запуск каждой программы мост подтверждает: это программа с другого ПК. Пока ПК управляют по сети и с телефона запуск недоступен.
- **Мои сборки.** В заготовке появилось поле «Что запускать у получателя» — мост сам подсказывает исполняемые файлы из папки сборки. Рядом с отправкой — поле **«Что нового в этой версии»**. Каждой отправке присваивается номер версии.
- **Показ закончился.** Если показ, который вы смотрели, закончился, окно показа и карточка в панели больше не исчезают: на них плашка «Показ закончился» и кнопка «Закрыть» посередине.
- **Показ перезапустили — он открывается снова сам.** Если тот же человек снова начал показ, окно и карточка переключаются на новый показ без ваших действий. По пожеланию из фидбэка.
- API:
  - `builds/presets` — поле `exe`;
  - `POST builds/send {…, note}`;
  - `POST builds/run | builds/stop {peer, name}`;
  - в `GET builds` → `received` — поля `n`, `note`, `exe`, `exeExists`, `running`, `history`.

## 3.7.0 — 28.10.2026
- **Ваш ключ.** У каждого пользователя теперь есть постоянный ключ Ed25519 — личность для игр и приложений.
  - Секрет хранится на этом ПК. В Windows он под защитой учётной записи (DPAPI) и никуда не отправляется.
  - «Настройки» → **«Ключ»**: отпечаток, **резервная копия** под паролем (Argon2id + XChaCha20-Poly1305), **восстановление** из копии на новом ПК и **смена ключа**, если ключ мог попасть к чужим.
  - Прежние ключи остаются на ПК: ими мост подписывает переход «старый → новый».
- **Приложения не видят основной ключ.** Каждому издателю мост выводит свой ключ, поэтому разные издатели не могут связать одного человека.
  - Приложение с правом «Ваш ключ для этого издателя» получает свой ключ и может только **попросить подписать** строку. Мост сам подставляет приложение, издателя, назначение и время: `most-sign/v1 / app / pub / purpose / ts / данные`.
  - Вход (`login`) от приложения с проверенным издателем подписывается без вопроса. Остальное — после вашего согласия; согласие действует до перезапуска моста.
  - Назначения `activity`, `presence`, `receipt`, `revoke` подписывает только сам мост.
- **Подпись издателя.** Пакет приложения можно подписать ключом издателя: `bridge app keygen`, затем `bridge app pack <папка> --key <файл>` (или `bridge app sign`, `bridge app verify`).
  - В окне разрешения видно, кто издатель и проверена ли подпись.
  - Пакет с неверной подписью не принимается. Изменённая папка разработчика просто считается «без подписи».
  - При передаче от соседа приложение, подписанное издателем, обновляется только пакетом того же издателя.
- **Интернет для веб-приложений** — по списку `network` в app.json: только точные адреса `https://` и `wss://`. Список показан в окне разрешения; если он изменился, мост спросит снова. Остальные адреса из рамки по-прежнему закрыты.
- **Ключ участника в сеансе.** Если у приложения есть право на ключ, у участников (`members`, событие `member`, билет) есть `key` — их ключ для издателя этого приложения.
- ID `most`, `bridge` и `system` приложениям брать нельзя.
- Unity SDK 3.7.0: `client.Identity.Get()`, `client.Identity.Sign(purpose, payload)`, `MostMember.Key`. Веб-SDK: `most.identity.get()`, `most.identity.sign(purpose, payload)`.
- API:
  - для приложений — `GET {MOST_API}/identity`, `POST {MOST_API}/identity/sign {purpose, payload}`;
  - локально — `GET identity`, `POST identity/export {password} | identity/import {file, password} | identity/rotate`, `GET apps/identity?id=`, `POST apps/identity/sign {id, purpose, payload}`, `POST apps/identity/answer {ask, ok, remember}`;
  - в `GET apps` — поля `publisher`, `publisherFp`, `sigNote`, `network` и список `signAsks`.

## 3.6.0 — 26.10.2026
- **Передача приложений соседям.**
  - В меню по правой кнопке на ярлыке — «Отправить соседям…». Можно выбрать нескольких соседей.
  - Папка приложения сама упаковывается в `.most-app`; готовый пакет уходит как есть. В пакет не попадают `.git`, `node_modules` и отладочные папки Unity (`…_BurstDebugInformation_DoNotShip`, `…_BackUpThisFolder_ButDontShipItWithYourGame`).
  - У соседа на рабочем столе приложений появляется «Предлагают соседи»: имя, версия, от кого, размер. Видно, новое ли это приложение или обновление (например, «обновление с 1.0.0»), и есть ли в нём программа. В открытом приложении число предложений показано на кнопке «‹ Все приложения».
  - Пакет скачивается, **только если сосед нажмёт «Принять»** — по подписанной связи мостов, потоком, до 4 ГБ. Мост проверяет sha256 и то, что в пакете то же самое приложение, и кладёт его в «приложения». Прежняя версия уходит в корзину моста.
  - Запускается полученное приложение, как и любое новое, только после разрешения хозяина ПК. Если изменились программы или права, мост спросит разрешение снова; если только интерфейс — нет.
  - Копию для разработки (приложение, лежащее папкой) пакет не перезаписывает: мост скажет, что её нужно обновить самому.
- **«Взять у хоста».** Если сосед по каналу уже играет в приложение, которого у вас нет, в полосе «Идёт сейчас» кнопка «Войти» сменяется на «Взять у <хост>». Если у вас другая версия протокола, появится «Обновить у хоста». Пакет скачивается сразу, потом остаётся разрешить приложение и войти. Само отдаётся только приложение, которое сейчас идёт в сеансе в вашем общем канале; остальное — только через «Отправить соседям».
- Запретить передачу приложения можно полем `"share": false` в app.json.
- Пока ПК управляют по сети, приложения не отправляются и не принимаются.
- Исправлено: в меню ярлыка пункты «Права и о приложении…» и «Открыть в отдельном окне» иногда не срабатывали.
- В полосе «Идёт сейчас» видны название и версия приложения у хоста.
- API: локально — `POST apps/share {id, peers}`, `POST apps/offer/accept {offer}`, `POST apps/offer/decline {offer}`, `POST apps/take {peer, id}`; в `GET apps` — `offers`. Между мостами — `POST /peer/apps/offer`, `POST /peer/apps/request`, `GET /peer/apps/pkg?offer=`.

## 3.5.0 — 26.10.2026
- **Сеансы приложений в голосовом канале.** Сетевое приложение (игра, общий инструмент) начинает сеанс с теми, кто сейчас в вашем канале. Лобби и серверы не нужны: кто откроет то же приложение в том же канале, попадёт в тот же сеанс. Вышли из канала — вышли и из сеанса.
  - Хост — ПК, начавший сеанс. Остальные ходят к нему через свои мосты по уже подписанной связи мостов. Если хост пропал, у остальных сеанс заканчивается с понятной причиной.
  - Три способа доставки:
    - надёжно — до 1 МБ, по порядку;
    - быстро — до 1200 байт, теряется при перегрузке;
    - последнее по ключу — для позиций и курсоров: устаревшее не доставляется.
  - **Общее состояние.** JSON у хоста, правки по пути, одинаковый номер правки у всех. Вошедший позже получает его целиком.
  - **Присутствие, часы сеанса и задержки.** Часы — общие, по хосту.
  - Можно вести игру через **свой сервер**: хост раздаёт строку подключения, а каждый участник получает билет, который сервер проверяет у моста.
  - Версия протокола приложения (`net.proto`) должна совпадать: старые сборки не войдут в сеанс новых.
- **«Идёт сейчас в канале»** — полоса на рабочем столе приложений: что уже запущено у соседей по каналу, кто в сеансе, и кнопка «Войти».
- **Журнал активности.** Мост записывает только факты, без содержимого: минуты в канале и разговора, показ экрана, сообщения в чатах, правки доски, пинги, отправки, вход в канал. Журнал хранится 30 дней. Приложение с правом «Видеть вашу активность» читает его — например, игра начисляет награды, в том числе за время, пока была закрыта.
- **Подключение редактора.** Unity или другая среда просит подключиться как ваше приложение, мост спрашивает вас в панели. Подключение действует до перезапуска моста. Ответа одновременно ждут не больше трёх запросов.
- **Unity SDK** — пакет `com.exerussus.most` в `sdk/unity/`, ставится через Package Manager по git-ссылке `https://github.com/exerussus/bridge.git?path=/sdk/unity/com.exerussus.most`.
  - Сеансы, отправка байтов, общее состояние, присутствие, часы.
  - Свой сервер, хранилище, уведомления, журнал активности.
  - Имитация плохой сети в редакторе.
  - «Мост → Собрать приложение»: своё окно или WebGL прямо в папку моста, с app.json.
  - К сетевой библиотеке не привязан: формат сообщений ваш.
- Веб-SDK: `most.session.*` и `most.activity.*`. Новый пример `examples/apps/mice` — курсоры всех в канале, точки по щелчку, общий счёт.
- Приложению с одним `net` в app.json (без интерфейса, окна и кнопок) окно не нужно: такое «сетевое» приложение можно разрешить и подключаться к нему из редактора ещё до первой сборки.
- Чего пока нет:
  - отдельного UDP для «быстро» — сейчас эти сообщения идут по связи мостов и отбрасываются при перегрузке;
  - передачи роли хоста другому участнику;
  - общих курсоров поверх окна моста.
- API: WebSocket `/bridge/v1/app/net` (своё окно и служба — по токену, веб — по пропуску панели), `/bridge/v1/peer/net` (между мостами), `GET|POST /bridge/v1/app/dev`, `GET /bridge/v1/app/ticket`, `GET /bridge/v1/app/activity`; локально — `GET apps/net`, `POST apps/net/channel | apps/net/ticket | apps/dev/answer | apps/activity/report`, `GET apps/activity`. Подробно — API.md, «Сеансы приложений».

## 3.4.0 — 26.10.2026
- **Новый раздел «Приложения»** (в меню под «Каналами») — свой набор приложений на каждом ПК, которыми вы управляете руками прямо из моста.
  - Рабочий стол ярлыков: поиск, перестановка перетаскиванием, меню по правой кнопке (открыть, в отдельном окне, служба, журнал, права, папка, отозвать, убрать в корзину моста).
  - Открытые приложения — вкладками; при переходе на другие разделы моста они не перезагружаются. **«В окно»** — приложение в отдельном окне, его можно унести на другой монитор.
  - Приложения лежат в папке **«приложения»** рядом с «отправкой»: папка с `app.json` или пакет **`.most-app`** (можно просто перетащить в окно). Мост подхватывает новое и изменённое за пару секунд, без перезапуска; правка интерфейса папки сразу перезагружает открытое приложение.
  - Три вида: **веб-интерфейс** (в изолированной рамке), **своё окно** (сборка Unity, любой exe — мост запускает и показывает состояние) и **кнопки** (команды с параметрами, окно рисует мост). Любому можно дать **фоновую службу**: мост запускает её, сам выбирает порт, пишет вывод в журнал приложения и гасит, когда приложение закрыто (или держит всегда — `run: "always"`).
  - **Ничего не запускается без вашего разрешения.** При первом открытии — окно: что именно запустится на этом ПК и какие права дать (галочки можно снять). Разрешение привязано к отпечатку программ и прав: поменялись — мост спросит снова; правка одного интерфейса — нет.
  - Изоляция: интерфейс приложения не видит панель и ключ моста, в мост ходит только через панель (права проверяются там); служба и своё окно — по своему токену с правами ровно этого приложения. Пока этим ПК управляют по сети — приложения не запускаются и ничего не меняют; с телефона раздел недоступен.
- **Для разработчиков приложений:** SDK `most-app.js` (`<script src="/most/sdk.js">` → `most.*`: хранилище, выбор и сохранение файлов, служба, уведомления, заголовок и счётчик вкладки, отдельное окно, тема, файлы, перетащенные на вкладку), захват мыши и клавиатуры (право `input.capture`), команды `bridge app new | check | pack`, пример `examples/apps/primer` (заметки, файлы, уведомления, захват ввода — основа будущего пульта ТВ).
- API: `GET apps`, `POST apps/allow | revoke | remove | start | stop | touch | action | import`, `GET apps/log`, `GET|POST apps/store`, `apps/svc/<id>/…` (прокси к службе); для служб — `/bridge/v1/app/me | store | notify | toast` (заголовок `X-Most-App`).

## 3.3.5 — 26.10.2026
- **Сборки — отдельная подвкладка с заготовками** («Отправка» → «Сборки»). Слева — список ваших сборок (проектов), справа — настройки выбранной: название, папка, кому (можно нескольким соседям сразу), режим по умолчанию и игнор. Всё сохраняется само; новая версия — «Упаковать и отправить» у нужной заготовки, ничего заново настраивать не нужно. «Копия» — заготовка на основе текущей. Прежняя одиночная сборка стала первой заготовкой.
- **Игнор сборки** — как .gitignore, по строке на шаблон: `Library/` (папка на любой глубине), `*.pdb`, `путь/от/корня`, `**/Cache/` (любая глубина), `!Нужное.pdb` — вернуть исключённое, `#` — комментарий. Кнопки быстро добавляют частое: Unity — `*_BurstDebugInformation_DoNotShip/` и `*_BackUpThisFolder_ButDontShipItWithYourGame/`, `*.pdb`, `*.log`. Общий игнор моста тоже действует.
- **Предпросмотр**: сколько файлов и мегабайт войдёт в архив, что отсеется и каким правилом (с примером файла), самые большие из входящих — пересчитывается, пока правите.
- В истории отправок — сколько файлов отсеяно игнором.
- API: `GET|POST builds/presets`, `POST builds/preview {path, ignore} | {preset}`, `POST builds/send {preset, mode?}`; в `GET builds` — `presets`.

## 3.3.4 — 26.10.2026
- **Статус обновляется сразу.** Выбрали статус или сняли его — соседи в канале видят это за доли секунды (раньше — только после очередного обмена с мостом, бывало и через полминуты). Картинка статуса подтягивается свежая.
- **«Связь восстановилась» вместо приветствия.** Если сосед всё это время сидел в канале, а у кого-то из вас пропадала сеть, при восстановлении не играет его звук входа и не пишется «зашёл» — звучит короткий отдельный сигнал и «Связь с … восстановилась». Признак шлёт сам клиент соседа (вошёл ли он только что).

- **Вкладка «Агенты».** Claude на одном ПК поручает задачу Claude на другом, видит ход работы в реальном времени и получает итог. Продолжение идёт в той же сессии — исполнитель помнит контекст.
- **Исполнитель, режим «сам запускает Claude»:** мост на каждое поручение запускает консольный Claude Code в фоне. Ограничения: время, сколько одновременно, предел расходов, режим разрешений (по умолчанию auto).
- **Исполнитель, режим «ждёт сессию Claude»:** хватает Claude Desktop. Поручение ждёт, коллега говорит своему Claude «возьми задачу из моста». В трее уведомление.
- **Инструменты моста для Claude (`bridge mcp`):** поручить, ждать, остановить, обменная папка, отправить файл. Готовая команда подключения — в панели.
- **Обменная папка с агентом** — одна кнопка «＋ обмен с …».
- **Удаление задач и записей** у всех участников. Вернуть можно: фильтр «удалённые» → «Вернуть». В консоли — `bridge delete` / `bridge restore`.
- Версия в панели кликабельна: «Что нового» — этот журнал.

## 2.4.0 — 20.10.2026
- **Отдельное окно показа экрана** — теперь полноценная страница. Двойной щелчок, клавиша F или кнопка — во весь экран на том мониторе, где стоит окно. Раньше двойной щелчок включал и сразу выключал полный экран.
- Когда показ закончился, окно пишет об этом; если закрыть окно, показ возвращается в панель.
- **Звуки в каналах:** вход и выход, микрофон, звук (наушники), начало и конец показа экрана — свои и чужие. Отключаются галочкой «звуки».

## 2.1.0 — 20.10.2026
- **Каналы (как в Discord):** зашёл — и ты в разговоре. Есть вход «без голоса», только для экрана.
- **Индикация у всех участников:** микрофон выключен, звук выключен, без голоса, показывает экран, смотрит чей-то показ.
- **Показ экрана — в канал.** Можно показывать несколько окон сразу, чужой показ открывается в отдельном окне. Видео передаётся только тем, кто смотрит.
- Если участники не соседи друг другу, сигналы передаёт ПК владельца канала.
- **Ход передач:** процент, скорость, сколько осталось — у обеих сторон.
- **Ограничение скорости** отдачи и приёма (Мбит/с). Предел размера файла по умолчанию снят.
